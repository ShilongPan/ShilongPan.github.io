## 0 · How the résumé is built (read once)

The résumé is a Jekyll site. Content lives in **3 kinds of files**:

1. **Entries** — one Markdown file per résumé item, under `_resume_entries/<section>/`.
   Each file has a YAML front-matter block (`title`, `organization`, `dateline`,
   `order`, `skills`) followed by one description paragraph.
   - `order` = sort position **within that section only** (lower number = higher).
   - `skills` = a list of **kebab-case IDs** that must all exist in the registry.
2. **Skills registry** — `_data/skills.yml`. The single source of truth for the
   skills panel. Every ID used in any entry MUST exist here (or the site logs a
   console warning about "orphaned tokens").
3. **Layout** — `_layouts/resume.html` renders the sections (Employment, Academia,
   Involvements, Awards, Interests) sorted by `order`. **Do not edit this file.**

**Rules that apply to EVERY edit:**
- Keep kebab-case IDs (lowercase, hyphens, no spaces). `creative direction` → `model-direction`,
  `problem solving` → `problem-solving`, `safety awareness` → `safety-awareness`.
- Every `organization` value is the "subheading". Replace it exactly as instructed.
- Do not delete the description paragraph unless told to delete the whole file.
- After ALL edits, renumber `order` per the tables in Section 6.
